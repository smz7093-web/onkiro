# 온기로 AI 설계 문서

- 작성: 2026-10-26 · 대상 코드: `functions/src/ai/`, `web/src/components/diagnose/`
- 원칙 한 줄: **금액과 판정은 사람이 정한 기준값(단가 DB·가정값·판정표)이 계산하고, AI는 그 사이의 "보는 일·읽는 일·설명하는 일"을 맡는다.**

## 1. AI가 하는 일과 하지 않는 일

| 구분 | AI가 하는 일 | AI가 하지 않는 일 (계산 엔진·사람이 함) |
| --- | --- | --- |
| 사진 분석 | 사진을 보고 체크리스트 답을 **제안** (누수·균열·지붕·욕실·주방 등) | 답을 확정하지 않는다. 회원이 '적용'을 눌러야 반영 |
| 등급 설명 | 실내 마감 하·중·상 등급별 자재 예시, 이 집에 맞는 등급 추천 | 금액을 만들거나 바꾸지 않는다. 금액은 단가 DB 계산값 |
| 가상 이미지 | 사진을 리모델링 후 모습으로 다시 그림 (참고용) | 실제 시공 결과를 약속하지 않는다. 'AI 가상 이미지' 상시 표시 |
| 인허가 안내 (RAG) | 인허가 자료에서 이 집에 맞는 자료를 찾아 항목별로 정리, 출처 표시 | 영업 가능·불가능을 판정하지 않는다. '법적 판정 아님' 상시 표시 |

왜 이렇게 나눴나: 견적은 같은 입력이면 언제나 같은 결과여야 한다(재현성, prd.md 7.3). LLM 출력은 매번 조금씩 달라서 금액·판정에 넣으면 재현성이 깨지고 근거를 설명할 수 없다. 그래서 AI 결과는 **제안·설명·참고 그림**으로만 쓰고, 숫자는 버전이 붙은 기준값으로 계산한다.

## 2. 기능별 구성

| 기능 | 함수 (Cloud Functions) | 모델 | 입력 | 출력 |
| --- | --- | --- | --- | --- |
| 사진 분석 (멀티모달) | `analyzeDiagnosisPhotos` | Claude Opus 5.5 | 진단 사진 최대 12장(부위 이름 포함) | 문항별 제안 답·확신도·이유·근거 사진 |
| 등급 설명 | `explainGrades` | Claude Sonnet 5.5 | 집 정보·체크리스트 답·등급별 견적(계산값) | 추천 등급·이유·등급별 자재 예시·주의점 |
| 가상 이미지 (멀티모달 생성) | `renderRemodel` | Vertex AI Gemini 2.5 Flash Image | 외관·방·욕실·주방 사진 1장 + 등급 | 리모델링 후 이미지 (Storage 저장) |
| 인허가 안내 (RAG) | `askPermitGuide` | Claude Sonnet 5.5 | 집 정보·운영 방식·묻는 말 + 검색한 인허가 자료 | 요약·항목(근거 자료 id 필수)·답하지 못한 것·출처 |

### 모델 선택 이유

- **사진 분석 = Opus**: 지붕 처짐, 천장 얼룩, 균열처럼 작은 단서를 읽어야 하고 틀리면 견적이 크게 달라진다. 정확도가 비용보다 중요하다.
- **등급 설명·인허가 안내 = Sonnet**: 글만 다루고, 근거(계산값·자료)가 이미 주어져 있어 정리·설명 능력이면 충분하다. 비용과 응답 시간을 줄인다.
- **가상 이미지 = Gemini 이미지 편집**: 원본 사진의 구도·형태를 유지한 채 마감만 바꾸는 이미지 편집이 필요하다. Vertex AI는 함수 서비스 계정으로 호출되어 별도 키 관리가 없다.
- 모델 이름은 `functions/src/ai/claude.ts`의 `AI_MODELS` 한 곳에서 바꾼다. 모델을 바꾸면 저장된 결과를 쓰지 않고 새로 만든다.

## 3. 프롬프트 설계

모든 Claude 호출은 같은 틀을 쓴다 (`claudeCaller`).

1. **시스템 프롬프트에 역할과 금지 사항**: 예) "금액을 새로 만들거나 고치지 마세요", "자료에 없는 법 조항·숫자를 만들지 마세요", "가능/불가능을 단정하지 마세요", "특정 상표는 쓰지 마세요".
2. **사용자 메시지에 구조화된 사실**: `[집 정보]`, `[상태 체크리스트]`, `[등급별 견적 — 변경 금지]`, `[인허가 자료]`처럼 구획을 나눠 넣는다.
3. **도구(tool) 입력 형식으로만 답하게 함 (구조화 출력)**: JSON 스키마(필수 필드, enum, 개수 제한)를 도구로 주고 "도구 한 번 호출로만 답하라"고 지시한다. 화면은 자유 글이 아니라 정해진 필드만 보여준다.
4. **서버에서 응답을 다시 검사**: `parseGradeExplanation`, `parsePhotoSuggestions`, `parsePermitGuide`가 형식·길이·허용값을 확인한다. 틀리면 실패로 처리하고 화면에는 "AI가 응답하지 않습니다"를 보여준다.
5. **팀이 정한 기준을 프롬프트에 넣어 어긋남 방지**: 등급 설명에는 팀이 확정한 등급 콘셉트·대표 마감(10/19)을 넣어, AI 자재 예시가 카드 내용과 다르지 않게 한다.

가상 이미지 프롬프트는 영어로 쓰고(이미지 모델 정확도), 버전(`RENDER_PROMPT_VERSION`)을 붙여 바꾸면 저장된 이미지를 다시 만든다.

## 4. 인허가 RAG (검색 증강 생성)

인허가는 법령·지자체 기준이 바뀌고 틀리면 피해가 커서, LLM의 기억에 맡기지 않고 **팀이 관리하는 자료에서 찾아 근거로만 쓰게** 했다.

```
집 정보(주용도·도로·지붕·대장 유무·연면적) + 운영 방식 + 묻는 말
        │
        ▼
① 검색 (retrieve, functions/src/ai/permits.ts)
   인허가 자료(permitKnowledge) 중 점수 상위 6개
   · 주제 태그: 기본 주제(민박·소방·보험 등) 1점, 이 집의 주의 신호 주제(맹지·슬레이트·무허가·위탁 등) 3점
   · 묻는 말과 낱말(두 글자 묶음) 겹침 비율 × 6점
        │
        ▼
② 생성 (Claude Sonnet, permit_guide 도구)
   "자료에 적힌 내용만 근거로, 항목마다 근거 자료 id를 붙여라"
        │
        ▼
③ 검증 (parsePermitGuide)
   찾은 자료에 없는 id는 지우고, 근거가 하나도 없는 항목은 버림 → 지어낸 항목이 화면에 나가지 않음
        │
        ▼
화면: 항목별 [근거 번호] + 근거 자료 목록(제목·출처·법령 링크·'담당자 검토 전' 표시) + '법적 판정 아님'
```

- **자료 관리**: 관리 화면 `/admin/permit-knowledge`에서 담당 팀원(부동산개발 원일, D7)이 자료를 추가·수정하고 '검토 완료'를 표시한다. 배포 없이 다음 질문부터 반영된다. 저장된 자료가 없으면 기본 자료 16개(PM 초안)로 검색한다.
- **임베딩 대신 태그+낱말 검색을 쓴 이유**: 자료가 수십 개 규모이고, 이 집의 신호(맹지·슬레이트 등)는 건축물대장·토지 정보에서 정확히 나오므로 태그로 고르는 편이 더 정확하고 설명 가능하다. 같은 입력이면 같은 자료가 뽑힌다(테스트 가능). 자료가 수백 개로 늘면 임베딩 검색(Vertex AI 텍스트 임베딩)으로 바꾼다.
- **답하지 못한 것**: 묻는 말 중 자료에 근거가 없으면 `unanswered`로 따로 보여주고 관할 시·군청 확인을 권한다.

## 6. 개인정보·AI 윤리

- **AI 생성 표시**: 가상 이미지에 "AI 가상 이미지 · 실제 시공 결과와 다를 수 있음", 등급 설명·인허가 안내 아래에 "AI가 … 쓴 참고 설명/안내" 문구를 항상 붙인다. 사진 분석은 '제안'으로만 보이고 회원이 직접 적용한다.
- **동의**: AI 기능 앞에 선택 동의(해외 AI 전송, `aiProcessing`)를 받는다. 화면뿐 아니라 서버 함수도 동의 기록을 확인한다(`assertAiConsent`). 동의하지 않아도 견적·수익 계산은 모두 쓸 수 있다.
- **보내는 정보 최소화**: 주소는 AI에 보내지 않는다. 사진은 브라우저에서 EXIF(위치 등)를 지운 뒤 올린다. 로그에 키·사진을 남기지 않는다.
- **삭제**: 진단을 지우면 AI 결과 문서와 가상 이미지 파일도 함께 지운다(`cleanupAssessmentAi`).
- **단정 금지**: 견적은 추정치, 인허가는 법적 판정 아님, 사진으로 구조 안전을 판단하지 않음(prd.md 1.2).

## 7. 테스트

AI를 실제로 부르지 않고 가짜 호출로 검사한다 (`functions/src/ai/*.test.ts`).

- 입력 검사(형식이 틀리면 거부), 프롬프트에 필요한 사실이 들어가는지, 응답 검사(허용값·길이·개수)
- 인허가 RAG: 주의 신호별로 맞는 자료가 검색되는지(슬레이트 → 석면 자료, 맹지 → 도로 자료, 창고 → 용도변경 자료), 묻는 말 검색, 같은 입력 같은 결과, **찾은 자료에 없는 근거 id를 붙인 항목을 버리는지**
- 모델 배정(`AI_MODELS`)이 바뀌면 테스트가 알려 준다
